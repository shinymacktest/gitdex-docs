# Purpose and Overview

GitDex is an interactive documentation viewer and AI-powered chat assistant designed to make repository content more accessible and searchable. By bridging the gap between static documentation and active inquiry, GitDex allows users to explore codebase information through a structured documentation interface while simultaneously engaging in natural language conversations with the repository's content.

## Core Functionality

The application provides two primary modes of interaction:

1.  **Interactive Documentation Viewer**: GitDex renders codebase documentation into a structured, searchable web interface. It utilizes the **Fumadocs** engine to transform MDX files into a navigable page hierarchy, providing a polished reading experience for technical documentation.
2.  **Chat Assistant**: An integrated chatbot enables users to converse directly with the repository content. This assistant is designed to answer questions, clarify technical details, and provide context derived from the documentation, leveraging advanced generative AI.

## Key Technologies

The client is built using a modern web stack optimized for performance and developer experience:

*   **Framework**: [Next.js](https://nextjs.org/) utilizing the **App Router** for dynamic routing and efficient rendering.
*   **Documentation Engine**: [Fumadocs UI](https://fumadocs.vercel.app/) for MDX rendering and managing the documentation hierarchy.
*   **Chat Interface**: [assistant-ui](https://www.assistant-ui.com/) for the interactive AI chat components.
*   **Styling**: [Tailwind CSS](https://tailwindcss.com/) for responsive and consistent UI design.
*   **Runtime**: [Bun](https://bun.sh/) for package management and script execution.
*   **Icons**: [Lucide React](https://lucide.dev/) for visual elements.

## High-Level Architecture

The application functions as a frontend client that interacts with a backend API to fetch and process repository data.

*   **Routing**: The system uses dynamic routing to handle various repositories, following a structure of `[owner]/[repo]`.
*   **Data Flow**: The client fetches documentation and repository metadata, which is then rendered via the Fumadocs engine. When a user interacts with the chat assistant, requests are routed through the client's API to the integrated AI services.

For detailed setup instructions, including dependency installation and environment configuration, refer to the [Getting Started](Getting%20Started.md) guide.
