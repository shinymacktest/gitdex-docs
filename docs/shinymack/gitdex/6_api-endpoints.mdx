# API Endpoints

This document provides an overview of the client-side API routes within the GitDex application. These routes act as a proxy or interface between the Next.js frontend and the backend services (such as the GitHub API or the dedicated GitDex backend server defined by `NEXT_PUBLIC_API_URL`).

## Indexing Content

The indexing route triggers the backend process to crawl and index a specific repository for documentation and chat capabilities.

### `POST /api/index`

This endpoint proxies requests to the backend's indexing service.

**Request Body**
The request must be a JSON object containing:
- `repoUrl` (string): The URL of the repository to index. Required.
- `force` (boolean, optional): If true, forces a re-indexing of the repository.

**Responses**
- `200 OK`: Returns the indexing task result from the backend.
- `400 Bad Request`: Returned if `repoUrl` is missing.
- `500 Internal Server Error`: Returned if an unexpected error occurs during the proxy request.

## Searching Documentation

The search route provides a way to find repositories using the GitHub Search API. This is typically used to find repositories to load into the GitDex viewer.

### `GET /api/search`

Queries GitHub for repositories based on a search string.

**Query Parameters**
- `q` (string): The search term. The search checks for matches within the repository `name`, `full_name`, and `description`.

**Responses**
- `200 OK`: Returns a JSON object containing an array of `items`. Each item represents a repository found. If no query is provided or an error occurs, an empty array is returned.

**Implementation Details**
- Uses `@octokit/rest` to communicate with GitHub.
- Uses the `GITHUB_TOKEN` environment variable for authentication.
- The search performs a lightweight client-side filter on the results returned by GitHub to improve partial-name matching.
- The results are sliced to return a maximum of 7 items.
- [client/src/app/api/search/route.ts](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/client/src/app/api/search/route.ts)

**Hypothetical Example Request**
`GET /api/search?q=nextjs`

**Hypothetical Example Response**
```json
{
  "items": [
    {
      "name": "nextjs",
      "full_name": "vercel/nextjs",
      "description": "The React Framework for the Web"
    }
  ]
}
```

## Checking System Status

The status route checks whether a specific repository has been successfully indexed and is ready for use.

### `GET /api/status`

Proxies a request to the backend to retrieve the indexing status of a repository.

**Query Parameters**
- `owner` (string): The GitHub username or organization name. Required.
- `repo` (string): The repository name. Required.

**Responses**
- `200 OK`: Returns a JSON object representing the status (e.g., `{ "indexed": true }`). If the backend returns non-JSON content or fails to provide a status, it defaults to `{ "indexed": false }`.
- `400 Bad Request`: Returned if `owner` or `repo` parameters are missing.
- `500 Internal Server Error`: Returned if the proxy request fails.

**Implementation Details**
- Uses `NEXT_PUBLIC_API_URL` to locate the backend service (defaults to `http://localhost:3001` if not configured).
- [client/src/app/api/status/route.ts](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/client/src/app/api/status/route.ts)
