# API Gateway

The API Gateway serves as the single entry point for all client requests to the DaakDash system. It is responsible for routing requests to the appropriate microservices, enforcing rate limits to prevent abuse, and managing centralized configuration.

## Request Routing

The Gateway utilizes Spring Cloud Gateway to route incoming HTTP requests based on path predicates to downstream services.

## Rate Limiting

To protect the system from brute-force attacks and API hammering, DaakDash implements a Redis-backed rate limiting mechanism.

### IP-Based Key Resolution

The gateway identifies clients based on their IP address. The `RateLimitConfig` class defines a `KeyResolver` that prioritizes the `X-Forwarded-For` header (common in proxied environments) before falling back to the remote host address.

```java
@Bean
public KeyResolver ipKeyResolver() {
    return exchange -> {
        String forwarded = exchange.getRequest().getHeaders().getFirst("X-Forwarded-For");
        if (forwarded != null && !forwarded.isBlank()) {
            return Mono.just(forwarded.split(",")[0].trim());
        }
        var remote = exchange.getRequest().getRemoteAddress();
        return Mono.just(remote != null ? remote.getAddress().getHostAddress() : "unknown");
    };
}
```

### Rate Limit Specifications

Different routes have varying capacities to balance security and availability:

| Route | Replenish Rate | Burst Capacity | Purpose |
| :--- | :--- | :--- | :--- |
| `/api/auth/**` | 10 req/s | 20 | Prevent login/register hammering |
| `/api/track/**` | 20 req/s | 40 | Control tracking query volume |

## System Configuration

### Redis Integration
The Gateway connects to a Redis instance to maintain the state of rate limit buckets across multiple gateway instances.
- **Host**: `${REDIS_HOST:redis}`
- **Port**: `6379`

### Management and Observability
The gateway exposes several actuator endpoints for monitoring system health and performance:
- **Health Probes**: Enabled for container orchestration (e.g., Kubernetes/Docker).
- **Exposed Endpoints**: `health`, `info`, `prometheus`.
- **Metrics**: Percentile histograms are enabled for `http.server.requests` to provide detailed latency data.
