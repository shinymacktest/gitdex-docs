# Node Classification Rules

In the `cerebrorank` pipeline, nodes extracted from Wikipedia are categorized into specific entity types. This classification is performed using a keyword-based approach defined within the project configuration.

## Classification Logic

The classification mechanism relies on a "first-match wins" priority system. When evaluating a node, the system checks the keywords associated with each type in the order they are declared in the configuration. Once a match is found, the node is assigned that type, and no further rules are evaluated for that specific node.

This ordering is critical for preventing misclassification. For example, the `list` type is placed at the top of the hierarchy to ensure that a page titled "Lists of Marvel Comics characters" is classified as a `list` rather than a `character`.

## Configuration Definition

The rules are defined in [config.yaml](https://github.com/santrupt29/cerebrorank/blob/32f8ca14fe1a4de04497d11e942f9c7432d264d1/config.yaml) under the `node_type_rules` key.

### Supported Node Types and Keywords

The following table details the entity types and the specific keyword phrases used to identify them:

| Node Type | Identifying Keywords |
| :--- | :--- |
| `list` | "list of", "lists of" |
| `character` | "fictional character", "comics character", "marvel character", "avengers member", "superhero", "supervillain" |
| `film` | "cinematic universe film", "superhero film", "marvel film", "american film", "feature film" |
| `tv_series` | "television series", "tv series", "streaming series", "disney+ original", "disney plus", "marvel television" |
| `comic_series` | "comic book series", "comic book title", "marvel comics series", "ongoing series", "limited series", "comic book" |
| `person` | "film director", "comic book writer", "comic book artist", "american actor", "voice actor", "film producer", "screenwriter" |
| `company` | "comic book publisher", "film studio", "entertainment company", "production company", "marvel studios", "disney" |

## Examples of Classification

The following examples demonstrate how the rules are applied based on the content of the Wikipedia page title or description.

> [!NOTE]
> **Hypothetical Example: Priority Match**
> **Input:** "Lists of Marvel Superheroes"
> 1. The system checks the `list` category first.
> 2. It finds the match "Lists of".
> 3. **Result:** Classified as `list`. (The system does *not* proceed to check the `character` category).

> [!NOTE]
> **Hypothetical Example: Standard Match**
> **Input:** "Robert Downey Jr."
> 1. The system checks `list` (No match).
> 2. The system checks `character` (No match).
> 3. ...
> 4. The system checks `person`.
> 5. It finds the match "american actor" (assuming the context matches the keyword list).
> 6. **Result:** Classified as `person`.

## Summary of Implementation
- **Source of Truth:** [config.yaml](https://github.com/santrupt29/cerebrorank/blob/32f8ca14fe1a4de04497d11e942f9c7432d264d1/config.yaml)
- **Constraint:** Rule order is strictly enforced; earlier rules take precedence over later ones.
- **Scope:** Classification is limited to the specific keyword strings defined in the `node_type_rules` dictionary.
