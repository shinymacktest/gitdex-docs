# Getting Started

GitDex is an interactive documentation viewer and chat assistant. It enables users to browse codebase documentation rendered via Fumadocs and interact with a chatbot to converse directly with repository content.

## Prerequisites

This project uses [Bun](https://bun.sh/) as its runtime and package manager. Ensure you have Bun installed on your system before proceeding.

## Installation

1.  **Clone the repository** (if you haven't already).
2.  **Install dependencies** by running the following command in the `client` directory:

    ```bash
    bun install
    ```

    This will install the necessary packages including Next.js, Fumadocs for MDX rendering, and `assistant-ui` for the chat interface, as defined in [client/package.json](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/client/package.json).

## Configuration

To run GitDex, you must configure your environment variables. Create a `.env` file in the `client` directory and populate it with the following keys:

```env
GITHUB_USERNAME=your_github_username
GITHUB_TOKEN=your_github_personal_access_token
NEXT_PUBLIC_API_URL=http://localhost:3001
GOOGLE_GENERATIVE_AI_API_KEY=your_gemini_api_key
```

### Variable Details

| Variable | Description |
| :--- | :--- |
| `GITHUB_USERNAME` | Your GitHub username. |
| `GITHUB_TOKEN` | A GitHub personal access token for repository access. |
| `NEXT_PUBLIC_API_URL` | The URL of the GitDex backend API (defaults to `http://localhost:3001` for local development). |
| `GOOGLE_GENERATIVE_AI_API_KEY` | Your Google Gemini API key, used to power the interactive chat assistant. |

## Running the Application

### Development Mode

To start the development server with Hot Module Replacement (HMR) enabled via Turbopack, run:

```bash
bun run dev
```

Once the server is running, navigate to [http://localhost:3000](http://localhost:3000) in your web browser to view the application.

### Production Mode

To prepare the application for production, you must build the project and then start the production server:

```bash
# Build the optimized application
bun run build

# Start the production server
bun run start
```
