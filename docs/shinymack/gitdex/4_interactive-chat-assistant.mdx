# Interactive Chat Assistant

The Interactive Chat Assistant is a codebase-aware AI interface that allows users to converse with the contents of a repository. It is implemented using `assistant-ui` and integrated with Google Generative AI via the AI SDK.

## Overview

The assistant provides a conversational interface to explore repository architecture, locate API endpoints, and understand authentication flows. It operates as a slide-out modal that can be toggled from the bottom-right of the documentation viewer.

## Interface Implementation

### Assistant Modal
The `AssistantModal` component [client/src/components/assistant-ui/assistant-modal.tsx](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/client/src/components/assistant-ui/assistant-modal.tsx) manages the UI state and runtime configuration:

- **Responsive Design**: On mobile devices (width < 768px), the modal occupies the full screen and disables body scrolling when open. On desktop, it appears as a right-side panel.
- **Resizable Panel**: Desktop users can resize the panel width (between 360px and 50% of the window width) using a drag handle on the left edge.
- **Runtime Configuration**: It utilizes `useChatRuntime` and `AssistantChatTransport` to connect to the backend API.
- **Contextual Headers**: The transport layer includes custom headers to ensure the AI is aware of the specific repository being discussed:
  - `x-github-owner`: The repository owner.
  - `x-github-repo`: The repository name.

### Thread Management
The `Thread` component [client/src/components/assistant-ui/thread.tsx](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/client/src/components/assistant-ui/thread.tsx) handles the conversation flow and message rendering:

- **Message Viewport**: An auto-scrolling viewport that renders user and assistant messages.
- **Welcome State**: When a thread is empty, it displays a welcome screen with suggested prompts, such as explaining architecture or listing API routes.
- **Conversation Controls**:
  - **Reset**: Users can clear chat history via the `runtime.thread.reset()` method.
  - **Branching**: The `BranchPicker` allows users to navigate between different versions of the conversation.
  - **Editing**: User messages can be edited, which triggers a new response from the assistant.

## Integration and Limits

### Technical Stack
The chat interface is built using several specialized libraries defined in [client/package.json](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/client/package.json):
- `@assistant-ui/react`: Core framework for the chat UI.
- `@assistant-ui/react-ai-sdk`: Integration between `assistant-ui` and the Vercel AI SDK.
- `@ai-sdk/google`: Provides the connection to Google Generative AI (Gemini).
- `ai`: The underlying AI SDK for stream handling and tool usage.

### System Constraints
To ensure performance and resource management, the following limits are enforced within the `Thread` component [client/src/components/assistant-ui/thread.tsx](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/client/src/components/assistant-ui/thread.tsx):

- **Message Limit**: A maximum of 10 user messages per thread. Once reached, the composer is disabled and the user is prompted to reset the chat.
- **Attachment Limit**: A maximum of 5 total attachments across the conversation.

## API Interaction

The assistant communicates with the backend via a REST endpoint:
- **Endpoint**: `${NEXT_PUBLIC_API_URL}/api/chat`
- **Transport**: Handled by `AssistantChatTransport`, which manages the streaming of responses from the AI model to the client UI.
