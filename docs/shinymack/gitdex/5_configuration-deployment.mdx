# Configuration & Deployment

This section provides the technical guidelines for configuring the GitDex environment and deploying the application to production.

## Environment Setup

The GitDex client utilizes a structured configuration for its documentation and UI components, managed through the Fumadocs framework.

### Documentation Configuration

The documentation system is configured via `cli.json` and `source.config.ts`. This ensures that the MDX processing pipeline and UI components are correctly mapped.

#### UI and Component Aliases

The project uses a set of aliases to maintain a clean directory structure for the frontend. These are defined in the `client/cli.json` configuration:

| Alias | Path | Description |
| :--- | :--- | :--- |
| `uiDir` | `./src/components/ui` | Radix-UI based primitive components |
| `componentsDir` | `./src/components` | General application components |
| `blockDir` | `./src/components` | Documentation block components |
| `cssDir` | `./src/styles` | Global and module-specific styles |
| `libDir` | `./src/lib` | Utility functions and library wrappers |

#### MDX and Rendering Plugins

The documentation engine is extended to support complex visual representations. As defined in `client/source.config.ts`, the system integrates the `remarkMdxMermaid` plugin to enable the rendering of Mermaid diagrams directly within the MDX files.

```typescript
import { defineDocs, defineConfig } from 'fumadocs-mdx/config';
import { remarkMdxMermaid } from 'fumadocs-core/mdx-plugins';
```

## Deployment Workflow

The GitDex backend is architected for serverless deployment, specifically targeting the Vercel platform.

### Backend Deployment Logic

The server configuration is managed via `server/vercel.json`. The deployment is based on a single entry point (`index.ts`) using the `@vercel/node` runtime.

#### Build and Routing Configuration

The backend deployment follows a "catch-all" routing strategy to ensure all requests are handled by the main server logic.

```json
{
  "version": 2,
  "builds": [
    {
      "src": "index.ts",
      "use": "@vercel/node"
    }
  ],
  "routes": [
    {
      "src": "/(.*)",
      "dest": "index.ts",
      "headers": {
        "Cache-Control": "no-store, must-revalidate"
      }
    }
  ]
}
```

#### Production Cache Policy

To ensure that AI-generated responses and repository data remain current, the production deployment enforces a strict cache policy. All routed requests include a `Cache-Control` header set to `no-store, must-revalidate`, preventing the browser or intermediate proxies from serving stale content.
