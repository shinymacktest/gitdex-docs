# Configuration Guide

This guide explains how to customize the behavior of the CerebroRank pipeline. The system uses a dual-layer configuration approach: settings are defined in a human-readable [config.yaml](https://github.com/santrupt29/cerebrorank/blob/32f8ca14fe1a4de04497d11e942f9c7432d264d1/config.yaml) file, which is then loaded into a typed `Config` dataclass in [core/config.py](https://github.com/santrupt29/cerebrorank/blob/32f8ca14fe1a4de04497d11e942f9c7432d264d1/core/config.py).

## Crawl Scope and Seeds

To change the topic of the crawl, modify the following sections in `config.yaml`:

- **`seeds`**: A list of Wikipedia page titles that serve as the starting points for the Breadth-First Search (BFS) crawler.
- **`category_roots`**: A list of Wikipedia categories that the system uses to expand the "allowed-set" of pages.
- **`category_depth`**: The depth to which the system explores subcategories starting from the `category_roots` (e.g., `0` means only the root category is processed).

## BFS Limits and Controls

To prevent the crawler from expanding indefinitely and to respect Wikipedia's resources, the following parameters in `config.yaml` control the growth:

| Parameter | Description |
| :--- | :--- |
| `max_depth` | The maximum BFS hop distance from the seeds. |
| `max_nodes` | A hard cap on the total number of nodes to be crawled. |
| `max_new_nodes_per_page` | Limits the number of new nodes added to the queue per single page. |

## Algorithm Hyperparameters

The Stage 2 graph builder and ranking algorithms (PageRank and HITS) are configured via the following keys in `config.yaml`:

### PageRank
- **`pagerank_d`**: The damping factor (typically `0.85`).
- **`pagerank_tol`**: The L1 convergence threshold (e.g., `1.0e-6`).
- **`pagerank_max_iter`**: The maximum number of iterations before the force-stopping the algorithm.

### HITS (Hubs and Authorities)
- **`hits_tol`**: The convergence threshold.
- **`hits_max_iter`**: The maximum number of iterations.

## Configuration Implementation Details

### Typed Loading
The system uses [core/config.py](https://github.com/santrupt29/cerebrorank/blob/32f8ca14fe1a4de04497d11e942f9c7432d264d1/core/config.py) to load the YAML file into a `Config` dataclass. This provides IDE-friendly, typed access to the settings across the project.

### Handling Unknown Keys
The `load_config` function is in [core/config.py](https://github.com/santrupt29/cerebrorank/blob/32f8ca14fe1a4de04497d11e942f9c7432d264d1/core/config.py) is designed to silently ignore unknown YAML keys. This allows you to add comments or annotations to `config.yaml` without breaking the loader.

### Validation
If a required field (a field in the `Config` dataclass without a default value) is missing from `config.yaml`, the system will raise a `ValueError` during initialization.

## Example Customization

*Note: The following is a hypothetical example of how you might modify `config.yaml` to crawl a different topic.*

```yaml
# Hypothetical example: Changing seeds to focus on "Quantum Computing"
seeds:
  - "Quantum Computing"
  - "Quantum Mechanics"

category_roots:
  - "Category:Quantum Computing"

max_nodes: 500
pagerank_d: 0.90
```
