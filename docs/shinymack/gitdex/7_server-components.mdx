# Server Components

The GitDex server acts as the orchestration engine for the background document indexing pipeline. It manages repository scanning, Table of Contents (TOC) planning, and step-by-step document generation using Google Gemini. Once documents are generated, the server commits the output directly to the designated GitHub documentation repository.

## Architecture Overview

The server is built using the Express framework and runs on the Bun runtime. It utilizes a queue-based architecture to manage long-running indexing tasks.

### Core Technologies
* **Runtime**: Bun [server/package.json](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/server/package.json)
* **Web Framework**: Express [server/index.ts](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/server/index.ts)
* **Database/Queue**: Upstash Redis and Upstash QStash [server/README.md](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/server/README.md)
* **AI Integration**: Google Generative AI (via `@ai-sdk/google` and `@google/genai`) [server/package.json](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/server/package.json)
* **GitHub Integration**: Octokit [server/package.json](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/server/package.json)

## Implementation Details

### Request Handling and Security

The server implements specific middleware to support both standard client requests and webhook-based orchestration:

* **CORS Configuration**: Access is restricted to URLs defined in the `CLIENT_URLS` environment variable or any origin ending in `.vercel.app` [server/index.ts](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/server/index.ts).
* **Raw Body Capture**: To support QStash signature verification, the server captures the `rawBody` of incoming requests before they are parsed as JSON. This is achieved via a custom `verify` function in the `express.json` middleware [server/index.ts](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/server/index.ts).
* **Logging & Errors**: A `requestLogger` middleware is applied to all requests, and a global error handler catches unhandled exceptions, returning a `500 Internal Server Error` response [server/index.ts](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/server/index.ts).

### Routing Structure

The API is organized into several functional namespaces:

| Prefix | Description |
| :--- | :--- |
| `/api` | Routes handled by `jobsRoutes` [server/index.ts](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/server/index.ts) |
| `/api/dev` | Routes handled by `devRoutes` [server/index.ts](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/server/index.ts) |
| `/health` | Returns a JSON status object `{ "status": "ok" }` [server/index.ts](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/server/index.ts) |

## Dependencies

The backend relies on several specialized packages for its core workflows:

* **Repository Processing**: `repomix` is used for repository analysis [server/package.json](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/server/package.json).
* **Diagramming**: `mermaid` is included for handling diagrammatic content [server/package.json](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/server/package.json).
* **Token Management**: `js-tiktoken` is used for managing token counts, likely for AI context window constraints [server/package.json](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/server/package.json).

## Development Workflow

### Environment Setup

A `.env` file must be configured with the following critical variables [server/README.md](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/server/README.md):

```env
PORT=3001
CLIENT_URLS=http://localhost:3000
UPSTASH_REDIS_REST_URL=...
UPSTASH_REDIS_REST_TOKEN=...
QSTASH_TOKEN=...
BASE_URL=...
GITHUB_TOKEN=...
GITHUB_USERNAME=...
DOCS_REPO_OWNER=...
DOCS_REPO_NAME=...
GOOGLE_GENERATIVE_AI_API_KEY=...
```

### Commands

Using Bun, you can manage the server lifecycle with the following scripts [server/package.json](https://github.com/shinymack/gitdex/blob/fa39a44254f08e3d5bd99ae2467e2709092ef5f9/server/package.json):

* **Install**: `bun install`
* **Development**: `bun run dev` (runs with `--watch` mode)
* **Production Start**: `bun start`
